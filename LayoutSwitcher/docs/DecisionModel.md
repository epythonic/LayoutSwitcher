# Модель принятия решения о коррекции

Документирует порядок, в котором `TypingPipeline` решает, что сделать с
закоммиченным словом. Это **контракт**: код в
[`TypingPipeline.evaluate`](../Pipeline/TypingPipeline.swift) и
`preferredCrossLayoutDecisionBeforeVisibleCorrection` должен совпадать с этим
документом. При изменении порядка — обновляй оба.

Принцип разделения: **пайплайн оркестрирует, детектор детектирует.** Весь рендер
раскладок, словари, скоринг и same-language коррекции живут в `LayoutDetector`
(`mapping.render`, `dictionaries`, `wordMatchesAlphabet`, `decide`,
`decideVisibleTextCorrection`). Пайплайн только подбирает контекст и применяет
результат, не реализуя детекцию заново.

---

## Фаза 0 — Охранные проверки (`evaluate`)

В порядке; любая останавливает обработку слова:

1. идёт retype (`isRetyping`) → выход;
2. мастер-тумблер выключен (`appState.isEnabled == false`) → reset;
3. не удалось определить активный язык раскладки → reset;
4. snooze активен → reset (подавление);
5. режим презентации → reset (подавление);
6. разделитель `Enter`/`Tab` → reset (небезопасно автопереключать);
7. разделитель не из «безопасной» пунктуации → reset.

## Фаза A — видимый текст распознан (`visibleCorrectionLanguage != nil`)

Если у уже-набранного текста есть язык-кандидат:

1. **`preferredCrossLayoutDecisionBeforeVisibleCorrection`** (цепочка приоритетов
   ниже). Если она вернула решение:
   - `.keep` → reset, выход;
   - иначе → применить (источник = `preferredDecisionSourceLanguage`), выход.
2. Иначе → **same-language коррекция видимого текста**
   (`applyVisibleTextCorrection`). Если применилась — выход.

## Фаза B — восстановление русской ё из рендера

Если фаза A не сработала: слово, перечитанное в русской раскладке, — это
уверенное русское слово (`confidentRenderedText(.ru)`), которому нужна ё →
применить (`applyRenderedRussianYoCorrection`). Ограничено русским: ё —
единственная внутриалфавитная реставрация такого рода. (Сознательно не
обобщено — обобщение меняет поведение для других языков.)

## Фаза C — резерв: `detector.decide(...)`

Полный каскад детектора с включёнными фичами и `allowedTargetLanguages`:
non-convertible guard → длина → RO-диакритика → общий каскад однокоренных
коррекций (ё / двойная заглавная / дубль-буква) → активный dict-hit →
кросс-раскладочные dict-совпадения → n-gram fallback. Возвращает
`keep` / `ambiguous` / `switch…`.

## Цепочка приоритетов (Фаза A.1)

`DecisionContext` считается один раз на слово: `word`, `activeLanguage`,
`visibleLanguage`, заранее вычисленные `visibleDecision`
(same-language коррекция видимого текста) и `crossLayoutSwitch`
(layout-switch от «голого» детектора, если это разрешённое переключение).

Стратегии пробуются строго по порядку — **первая вернувшая решение побеждает**;
`nil` означает «нет мнения, дальше». `nil` всей цепочки → переход к Фазе A.2.

| # | Стратегия | Когда срабатывает |
|---|-----------|-------------------|
| 1 | `pendingSequenceContextDecision` | Идёт пакетный retype: перечитываем слово в целевом языке пакета, чтобы серия осталась в одном языке. |
| 2 | `recentAutoSwitchContextDecision` | Предыдущее слово только что автопереключено: распространяем тот же язык на текущее (с проверками времени/приложения/разделителя). |
| 3 | `visibleLatinOutranksRenderedDecision` | Видимый текст — настоящее латинское (EN/RO) слово: предпочитаем его same-language коррекцию или `keep`, а не реинтерпретацию между раскладками. |
| 4 | `visibleNonEnglishDictionaryDecision` | Видимый текст есть в словаре не-английского видимого языка: `keep` (или его same-language коррекция). |
| 5 | `renderedCrossLayoutCorrectionDecision` | Перечитка клавиш в другой включённой раскладке даёт уверенную same-language коррекцию (типичная «не та раскладка»). |
| 6 | `activeRenderedDictionaryOrLayoutSwitchDecision` | Рендер в активной раскладке сам по себе словарное слово; иначе — layout-switch от детектора (только если видимый язык совпадает с активным). |

Общие примитивы, чтобы не дублировать рендер+словарь:
- `confidentRenderedText(for:in:)` — рендер в язык + проверка, что это уверенное
  одно-язычное совпадение (отличается от видимого и `visibleCorrectionLanguage`
  сходится именно на этот язык). Используется стратегиями 1/2/5 и фазой B.
- `renderedContextDecision(for:target:)` — предпочесть буквальный рендер, если он
  уже словарное слово (иначе NSSpellChecker может предложить близкое слово вроде
  «мур» вместо «мир»), иначе — same-language коррекция. Используется стратегиями 1 и 2.

## Производительность и поток

Детекция выполняется **синхронно на main thread** в callback event tap (после
коммита слова). Это сознательно: алгоритм дешёвый — хеш-словари (O(1) lookup),
малая фиксированная bigram-модель и ограниченное число ре-рендеров на слово; в
горячем пути нет некэшированного I/O. Единственная системная зависимость,
`NSSpellChecker`, закэширована: членство — FIFO-кэш на 10k
(`SystemSpellCheckerDictionary`), подсказки — FIFO-кэш на 4k
(`CachedSpellingSuggestionProvider`). Поэтому вынос детекции в фон признан
ненужным — он добавил бы заметный риск конкуррентности ради неощутимой выгоды.
Регрессии стережёт `decideStaysWithinMainThreadBudget` в `LayoutDetectorTests`.
